## Oracle repair during round 001

The first 100-case candidate run with Z3's position-variable encoding was stopped after it spent over a minute on a larger construction; interrupting it returned `unknown`, so this is an execution failure, not an infeasibility answer. The change was to use an exact subset/last-task earliest-arrival dynamic program for bulk target checks, with a separate state bit when a second schedule must differ from the first. Earliest arrival dominates later arrival for the same remaining tasks and last compiler, so pruning is sound. The original Z3 encoding remains in `check.py`; the self-test cross-checks both methods against exhaustive permutation truth on 30 seeded four-task targets and on the hand examples. The corpus and source labels did not change. The rerun of `--self-test` passed. The bulk domain remains finite and runtime may grow exponentially with target task count; no solver timeout or unknown status is treated as NO.
